## 开工前必须统一的口径

### 1. 「某人总说话时长」不是「整场会话时长」

- 某人总说话时长：只筛该说话人的片段，求 `end - start` 之和。
- 整场会话时长：`max(end) - min(start)`；空数组返回 0。
- 两个值必须是两个不同的函数，否则 T18 的「打断次数/小时」很容易拿销售发言时长当分母。

### 2. 「问句数」按问号数，不按片段数

- 同时识别中文 `？` 和英文 `?`。
- 同一个 `TranscriptSegment.text` 里有两个问号，就是两个问句。
- 可以同时提供「找出含问句的片段」和「统计问号数」，不要把两者混成一个含糊函数。

### 3. 基础工具不负责业务语义

T17 只写通用纯函数。「客户首次主动发言」「进入业务话题」「异议是否被实质回应」都需要业务口径，不属于 T17。不要提前写 T18~T21。

### 4. 不要在基础函数内提前取整

时长直接返回秒数，保留 JavaScript 计算精度。只在验收输出时用近似比较或固定小数显示，不要把 `toFixed()` 后的字符串当返回值。

## 验收时你自己要盯的五件事

1. **真的在测实现**：`verifyTranscriptUtils.mjs` 必须 import `frontend/src/lib/transcript.ts`，脚本内不能重写一遍求和/计数算法。
2. **两种时长没混**：样本 A 的销售说话时长应是 1300.4 秒，整场时长是 1761.2 秒；两者不能由同一个含糊函数返回。
3. **问句按问号数**：样本 A 客户是 13 个问号，但只有 11 个片段含问号。如果输出 11，就是口径写错了。
4. **时间函数名有单位**：搜索导出的函数，任何返回时间数值的都应以 `Seconds` 结尾。
5. **没有越界**：不应出现破冰、打断、首次主动发言、卖点、异议或评分函数；那些分别属于 T18~T22。
