## 提交的部署资产

- `ops/deploy-production.sh`：校验 root、域名、依赖与证书；支持 Git 更新或显式离线 bundle；安装依赖、构建前端、保护既有数据库、发布静态文件、启动 PM2、切换 Nginx 并执行最终检查。
- `ops/ecosystem.config.cjs`：固定 API 名称、cwd、Node 22 TypeScript 启动参数、生产环境、日志、单实例、自动重启和 512MB 内存上限。
- `ops/nginx/xiaoshoufupan.woshimake.com.production.conf`：HTTP 跳 HTTPS、ACME 路径、TLS、SPA fallback、API 反代和 service worker 禁缓存。
- `ops/check-production.sh`：检查 Nginx、PM2、ping、Mock、0600 权限、Android/iOS 原生壳 CORS 白名单、陌生来源拒绝、四条 SPA 深链和 API/前端边界。

## 服务器执行与问题闭环

1. 源码包通过阿里云自动化运维上传到 `/root`，在 `/opt/xiaoshoufupan/repo` 离线解包；没有把密钥、证书或生产环境文件放进 Git。
2. 首次构建成功后，PM2 7.0.3 暴露两个兼容问题：`startOrReload` 首次运行异常，非标准 ecosystem 文件名又会被当作普通脚本。最终统一改为 `ecosystem.config.cjs` + `pm2 start`，正确进程名为 `xiaoshoufupan-api`。
3. 首次创建环境文件时发现 `umask 077` 影响后续静态目录，Nginx 日志明确报告 `Permission denied`。脚本把 umask 限制到子 shell，并在 release 复制后统一目录 0755、文件 0644。
4. 最终检查输出：`PASS: Nginx、PM2、Mock、权限、SPA 深链与 API 边界均通过。`
5. 重复部署检测到既有数据库并跳过 push/seed；再次发布后检查 PASS。正常重启 ECS 后约 50 秒，线上 API 和作战包恢复，报告 #7 与 S2/1 次状态仍在。
