用户的原始要求：

1. 现在画面上有些本来只应该保留 UI 按钮的地方，文字太多，要减少视觉噪音。
2. 客户、档案等内容整体太长，需要搜索框和快速跳转，帮助用户马上找到内容。
3. 日期不应要求用户手动输入，要使用日期/时间选择器，新建时默认当天日期。
4. 所有操作统一遵守：
   - 操作前，有预期；
   - 操作中，有反馈；
   - 操作后，可撤回；
   - 能选择就不输入；必须输入时提供提示、示例或推荐值。

执行纪律：

- 严格按 UX01 → UX02 → UX03 → UX04 → UX05 → UX06 串行执行。
- 每次只做一个任务。当前任务没有完成“现状检查 → 实现 → 自检 → 自动化验证 → 浏览器或模拟器实际验证 → 查看 diff → 更新 docs/进度.md → 独立 commit”前，禁止开始下一个任务。
- 不允许把多个任务做完后统一验证或统一提交。
- 每个任务完成后先自检，再向用户汇报：
  1. 改了哪些文件；
  2. 每处改动用大白话实现了什么；
  3. 执行了哪些验证命令，实际结果是什么；
  4. 用户应打开哪个页面、点什么、输入什么、应看到什么；
  5. 当前任务的 commit hash。
- 每个 commit 只包含当前任务文件。禁止使用 git add . 或 git add -A。
- 可以正常 push origin main，但禁止 force push、rebase 已推送提交、reset --hard 或覆盖用户文件。
- 遇到不相关的工作区改动必须保留并绕开，不能为了干净工作区而删除或重置。

本轮硬边界：

- 不做 T54，不切换 USE_MOCK=false，不调用真实 Dify 或 ASR。
- 不修改评分口径、AI 结果结构、客户 S1/S2/S3 规则、种子业务内容或数据库 schema。
- 不改域名、服务器、Nginx、PM2、Cloudflare、Android/iOS 包名和生产签名。
- 不新增第五个一级导航；仍保持“待办 / 新建 / 复盘 / 我的”四个一级入口。
- 不在生产环境创建、修改或删除业务数据。浏览器写操作使用本地后端和可恢复测试数据。
