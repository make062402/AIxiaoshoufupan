# UI 与交互优化总体验收清单

## A. 全局外壳

- [ ] 390×844 下顶部不被刘海或灵动岛遮挡，底部 Tab 不压住内容。
- [ ] 1440×900 下左侧导航正常，正文最大宽度与留白正常。
- [ ] 四个一级入口仍是待办、新建、复盘、我的。
- [ ] 主按钮、次按钮、返回动作的视觉层级一致。
- [ ] 页面没有大段重复解释，必要说明仍可找到。
- [ ] Tab 键焦点清楚，图标按钮有 aria-label，不只靠颜色表达状态。

## B. 待办 /todos

- [ ] 能快速找到待办；列表多时不必盲目滚动。
- [ ] 空截止日仍显示“未设截止日”，没有被自动写成今天。
- [ ] 设置截止日默认今天，可选今天、明天、下周。
- [ ] 修改、清除、完成操作都有处理中反馈。
- [ ] 完成状态和截止日修改可真正撤销；刷新后与数据库一致。

## C. 新建拜访 /new

- [ ] 已有客户使用下拉选择，不要求输入客户 ID。
- [ ] 拜访日期时间使用系统选择器，默认本地当天的未来时间。
- [ ] 有今天、明天、下周快捷选择。
- [ ] 提交前显示客户、场景、时间摘要。
- [ ] 提交中不能重复点击；成功和失败结果明确。

## D. 复盘 /reviews 与 /reviews/details

- [ ] 上传或粘贴两种模式的主操作清楚，没有重复说明挤占首屏。
- [ ] 必须输入的逐字稿有格式示例或一键样例。
- [ ] 客户、场景、来源、语言、行业优先使用下拉选项。
- [ ] 缺少必填项时明确指出具体字段。
- [ ] 分析过程中有反馈且不能重复提交。

## E. 复盘报告 /reviews/result 与 /reviews/report/:id

- [ ] 有章节级快速跳转。
- [ ] 原有指标到证据定位、逐字稿高亮和“返回当前指标”仍正常。
- [ ] 长逐字稿可搜索或快速定位，不破坏独立滚动。
- [ ] 保存报告前能预期会写入什么；保存中有反馈。
- [ ] 不可逆时明确提示，不显示假的撤销。
- [ ] 稳定报告 URL 刷新后仍可查看。

## F. 客户库 /me/customers

- [ ] 可按姓名、身份、联系方式、行业或核心需求搜索。
- [ ] 阶段或意向筛选可与搜索组合。
- [ ] 显示结果数量；无结果时可一键清空。
- [ ] 清空后恢复原列表和原排序。
- [ ] 长列表能快速回到搜索框或顶部。

## G. 客户档案 /me/customers/:id

- [ ] 顶部目录能跳到 8 项档案和人工意向。
- [ ] 移动端目录紧凑，不占据大量首屏。
- [ ] 必须输入项有示例；能枚举的角色、预算、优先级优先提供推荐或选择。
- [ ] 保存前能知道会保存整份档案；保存中禁用重复提交。
- [ ] 保存成功后可撤销到旧快照，刷新后真实一致。
- [ ] 客户原话时间点仍允许“10 月中旬”等自然语言。

## H. 作战包 /me/customers/:id/battlecard

- [ ] 主要章节可快速跳转并回顶部。
- [ ] 本次目标、风险、产品和话术的层级清楚。
- [ ] 没有因减字丢失“待确认”、风险或来源信息。
- [ ] S1/S2/S3 原有组装口径没有变化。

## I. 话术库、产品库、团队报告

- [ ] 话术可按内容、场景、行业搜索。
- [ ] 产品可按名称、行业、参数、卖点搜索。
- [ ] 团队报告可按客户或报告信息查找。
- [ ] 搜索不改变原始排序，清空后完整恢复。

## J. 配置 /me/config

- [ ] 安全说明没有因减字而丢失。
- [ ] 管理员令牌和 API Key 不被记录到浏览器持久存储、日志或截图。
- [ ] 保存前明确说明会替换服务器 Key，要求确认。
- [ ] 保存中有反馈、防重复提交；失败说明如何处理。
- [ ] 因无法安全读取旧 Key，不显示假的撤销入口。

## K. 原生与构建

- [ ] npm run lint 通过。
- [ ] npm run build 通过。
- [ ] 后端 npx tsc --noEmit 通过。
- [ ] iOS BUILD SUCCEEDED，模拟器实际启动。
- [ ] iPhone 刘海或灵动岛、底部安全区和日期选择器正常。
- [ ] Android assembleDebug 成功。
- [ ] 页面没有新增控制台错误或未处理 Promise。
- [ ] git diff --check 通过。
- [ ] 每个 UX 任务各有一个独立 commit，未混入旧交接文档。
