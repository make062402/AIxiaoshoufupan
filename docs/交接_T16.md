## 要你拍板的一件事

任务清单 T16 的验收原文是「随便改几条数据，跑这条命令后回到初始状态」。
「初始状态」是否包含**自增 id**，这句话没说死，而现状是不包含：

`clearAll()` 用的是 `DELETE` 而不是 `TRUNCATE`，SQLite 的 `sqlite_sequence` 不会被重置，
所以每灌一次，各表的 id 就往上涨一截。现在 products 的 id 已经是 51~60、reviews 是 31~36。

功能上完全没影响——所有外键都是用 `.returning()` 拿真实 id 串联的，全项目没有任何硬编码 id。
`docs/进度.md` 的 P4 记着这件事，当时的倾向是**无需处理**。

两个选择：

- **A（推荐）**：不动 id，把「初始状态 = 各表条数与内容一致」写清楚在 README 和 `进度.md` 里，P4 就地关闭。
  理由：id 连续与否对 Demo 毫无影响，加重置逻辑反而多一处可能出错的地方。
- **B**：在 `clearAll()` 里追加 `DELETE FROM sqlite_sequence`，让 id 每次都从 1 开始。
  代价：多一处对 SQLite 内部表的依赖；好处是「回到初始状态」这句话没有任何解释空间。

**开工前先把这个定下来**，不要让 agent 自己选。
